# Resource Policy Inventory

This inventory records the limit policy reset of 2026-11-14, which [ADR 0004](adr-0004-diagnostics-and-resources.md) adopts.

It classifies every limit-like constant in the product crates, as found by `rg -n "^\s*(pub(\([a-z]+\))? )?const [A-Z0-9_]*(MAX|LIMIT|CAP|BUDGET)[A-Z0-9_]*\s*:" crates/*/src --glob '!**/tests*'`, together with the parser defaults that the pattern does not match, and names every constant the reset removed.

## Policy

Hostile-input protection means memory safety, no panics, checked arithmetic, bounded allocation, and bounded recursion.

It does not mean bounded CPU time, which belongs to the caller; a compact input that fits the memory budget runs for as long as its work takes unless the caller cancels it through the operation's `stab_model::Cancellation` signal, described under [Cooperative Cancellation](#cooperative-cancellation).

Every materializing or executing operation has one admission dimension, a typed `stab_model::MemoryBudget` of conservatively counted retained bytes, admitted with checked arithmetic before allocation, RNG advancement, or output and followed by fallible reservation.

The budget defaults to one gibibyte, is caller-selectable through each operation's limits type, and is exposed on the CLI as the one Stab-native `--memory-budget SIZE` option.

Library budgets are per operation: each call admits its own storage against the budget value it is given.

## Command-Level CLI Budget

The CLI turns one `--memory-budget` into a command-level ledger.
Each stage receives the budget less the bytes that earlier stages still hold, and a stage's bytes return to the budget as soon as its storage is dropped.

| Stage | Admitted against | Held until |
| --- | --- | --- |
| Input text | The whole remaining budget | Parsing ends; the parser charges the text together with the model, so the text needs no separate hold |
| Parsed circuit or DEM | The remaining budget, charging source and model bytes together | Feedback inlining replaces it (`m2d --ran_without_feedback`), the plan is compiled (`sample`, `detect`, `m2d`, `sample_dem`, `plan sample`), the analysis returns (`analyze_errors`), the canonical text is written (`convert` stim to stim), or the side input's counts are read (`convert --circuit` and `--dem`); the hold is the retained model bytes `Circuit::from_stim_bytes_admitted` and `DetectorErrorModel::from_dem_bytes_admitted` report |
| Inlined feedback circuit (`m2d --ran_without_feedback`) | The budget less the parsed circuit's hold | The conversion plan is compiled; once the parsed circuit is dropped, `Circuit::admitted_bytes` replaces its hold |
| One-shot visible-measurement list (`sample --shots 1` with reference sample) | The budget less the parsed circuit's and compiled plan's holds | The command ends |
| Compiled plan (`sample`, `detect`, `m2d`, `sample_dem`) | The budget less the active circuit or DEM hold | The command ends, holding `plan.retained_bytes()` |
| Replay reader (`sample_dem --replay_err_in`) | The budget less the compiled plan's hold, admitted by `DemSamplingPlan::admit_replay_input` together with the smallest replay session (a one-record batch with its sampled-error planes) before the replay input is read | The command ends, holding `RecordStreamStorage::bytes` for the replay format and the error count in 64-record batches (one-record batches for PTB64, which reads whole groups as bit planes), plus for `01`, HITS, and DETS the transport buffer of a text cap that receives a quarter of what the reader and the smallest session leave; a refusal is `resource-limit-exceeded` with resource `active-batch-bytes` for the reader and smallest session together and is reported before any input is read or output is opened |
| Session, streaming run, retained replay records, analysis | The budget less the active holds (the compiled plan's hold for `sample`, `detect`, `m2d`, and `sample_dem`, plus the replay reader's hold for `sample_dem --replay_err_in`, plus `MeasurementToDetectionSession::retained_bytes` while `m2d` streams records; the parsed circuit's hold for `analyze_errors`) | The command ends |
| Record conversion storage (`convert`) | The budget less the side-input holds still active, which is all of it once the side inputs are released | The command ends, holding `RecordStreamStorage::bytes` for the input format, width, and batch size (the reusable batch, the PTB64 group, the first `r8` record's hits in at most one row, and the transport buffer at its peak: around one `b8` record or PTB64 group, and for `r8`, whose records decode as their bytes arrive, the fixed 64 KiB initial buffer whatever the width), plus `PackedShotBatch::storage_bytes` of each column batch split from a batch, plus `RecordEncoder::shot_major_scratch_bytes` of the primary and observable encoders; a refusal is `resource-limit-exceeded` with operation `record-conversion` and is reported before the reader buffers or allocates anything |
| Streamed text records (`m2d`, `convert`) | `RecordStreamStorage::max_text_record_bytes` of the budget less the holds still active when records are read (about half of it, so the line buffer, which grows to one byte past the cap and briefly holds its old allocation beside the new one, stays within that budget), which for `convert` include its record conversion storage | Each record is framed |
| Streamed text records (`sample_dem` replay) | `RecordStreamStorage::max_text_record_bytes` of a quarter of what the plan's hold, the reader's fixed storage, and the smallest replay session leave (about an eighth of it), held with the replay reader so the replay session and the retained records are admitted beside the line buffer at its peak | The command ends |

A stage refused while earlier stages hold bytes keeps its error class, code, exit status, and help text, and its message adds `earlier stages of this command hold N bytes of its M-byte memory budget`; JSON Lines diagnostics add `context.command_memory_budget` with `held_bytes` and `budget_bytes`.

## Classification

| Kind | Rule |
| --- | --- |
| Invariant | A format, representation, or Stim-semantic bound. Unchanged by the reset. |
| Nesting | The shared 256-level repeat-nesting envelope, which callers may tighten on operations that expose a nesting limit. |
| Byte budget | A `MemoryBudget` or a value derived from one. |
| Search budget | Explicit caller policy with a budget-exhausted result. Values unchanged by the reset. |
| Threshold | An implementation choice that selects storage, batching, or an algorithm and never rejects otherwise valid work. |
| Not a limit | Matched by the search pattern but not a resource limit. |

Circuit-materializing projections (circuit passes, flattening, feedback inlining, measurement-rich time reversal, and sampled-flow witness circuits) count circuit storage with the same sizes the parser charges: `size_of::<CircuitItem>()` (56 bytes on 64-bit targets) or `size_of::<CircuitInstruction>()` per item, 4 bytes per `Target`, and `advanced::circuit_declaration_admitted_bytes` per declaration.

Each of these operations admits every retained allocation it makes against the one caller budget, including the algebra values it builds, which receive the same byte count as an `AlgebraMemoryBudget`; the functions without a budget parameter use `MemoryBudget::DEFAULT`.
The unbudgeted flow checks keep failing a flow closed when the default budget refuses live tracker state or an extracted Pauli string; the `*_with_options` siblings report the refusal instead.
The sparse reverse tracker counts what its sets retain by buffer capacity, together with their map entries, the recycled-set pool, the merge and operand buffers, and any sensitivity held outside its maps while it is merged.
Each merge that may allocate first admits its worst-case growth, at most the sum of the merged lengths under amortized growth, so one wide instruction is refused before its sets outgrow the budget rather than after; uncounted map nodes and per-instruction term lists stay a few kilobytes beyond it.
The tracker folds a unitary repeat above one iteration into one slot transform built from a single basis tracker on its own undo stack, so nested unitary repeats cost one body undo per level and no native recursion, and the transform's compositions are admitted before they are built.
`sample_if_circuit_has_stabilizer_flows` in `stab-engine` is the default-budget, never-cancelled form of `sample_if_circuit_has_stabilizer_flows_with_options`.

## Cooperative Cancellation

`stab_model::Cancellation` is one cloneable signal: `Cancellation::new` creates a settable signal, `cancel` and `reset` set and clear it from any thread, and `Cancellation::never`, also the default, cannot be set and costs no allocation.
Operations given a set signal stop with a typed `Cancelled` outcome, either the error variant `Cancelled(stab_model::Cancelled)` of the operation's error type or a session's `Cancelled` run status, and the CLI reports the stable diagnostic code `cancelled`.
The CLI passes never-cancelled signals, because the process already stops on `SIGINT` and `SIGTERM`.

Analysis, flattening, and DEM loops poll through `stab_model::advanced::CancellationCountdown`, which loads the signal once every 1024 ticks; a tick is one interpreted instruction, repeat iteration, sampled or replayed error, or comparable bounded unit, so one tick can still be a large instruction.
Circuit-sampling and detection-sampling frame batches, detector and observable conversion, streaming window hand-overs, partial-delivery lane shifts, and the reference simulator instead charge an engine work countdown with the estimated work of each step, in units of about one nanosecond of lane-word or tableau work, and walk wide target, term, and plane lists in chunks charged one at a time; the signal is loaded once about every millisecond of work, and no clock is read.
The one step that is not split is a single reference-simulator collapse or fold comparison, whose work grows with the square of the qubit count: about 1.3 ms at 12,000 qubits.

| Operation | How the caller supplies the signal | Where it is polled | Outcome |
| --- | --- | --- | --- |
| Circuit sampling | `SamplingCompiler::cancellation`, or `SamplingSession::cancellation` for a session-local signal | Reference-sample simulation by tableau work, frame batches with their reference flips by lane-word work, and the shift that moves a partly delivered batch's remaining lanes to lane zero, plus between batches | `SamplingRunStatus::Cancelled` with only complete batches delivered, a finalized sink, and a resumable seeded stream, because a batch the cancellation interrupts is discarded with its random stream rewound and an interrupted lane shift keeps the planes it already moved and finishes in the next run; a streaming run stops the same way but cannot be resumed; during reference computation at session creation, `SamplingExecutionError::Cancelled` with nothing cached |
| Detection sampling | `DetectionConversionLimits::with_cancellation` on `DetectionSamplingCompiler::limits`, or `DetectionSamplingSession::cancellation` | Frame program, the clearing of its output planes, and conversion program by work, plus between batches | As for circuit sampling, with `DetectionRunStatus::Cancelled` |
| Measurement-to-detection conversion | `DetectionConversionLimits::with_cancellation` on `MeasurementToDetectionCompiler::limits`, or `MeasurementToDetectionSession::cancellation` | Reference-sample computation at compilation, sweep-correction frame program, the transpose of each input window, and conversion program | `DetectionError::Cancelled` from compilation; a batch cancelled before or during conversion returns `DetectionRunStatus::Cancelled`, delivers nothing, and leaves the session resumable because conversion consumes no random stream |
| DEM sampling and replay | `DemSamplingCompiler::cancellation`, `DemSamplerLimits::with_cancellation`, or the session's `cancellation` | Every visited DEM item and folded zero-shift error during compilation, and every sampled or replayed error and repeat iteration, plus between batches | `DemError::Cancelled` from compilation; `DemSamplingRunStatus::Cancelled` or `DemReplayBatchStatus::Cancelled` from a session, with counter-based streams keeping an in-batch cancellation resumable with the same seeded output |
| Sampled flow checking | `SampledFlowOptions::cancellation` | Before each flow, while building each augmented witness circuit, and by each flow's sampling compilation and session as for circuit sampling | `SampledFlowError::Cancelled`; a cancelled session's partial samples never become a verdict |
| Circuit-to-DEM analysis | `ErrorAnalyzerOptions::cancellation` | Every analyzed instruction and repeat iteration, folded or unrolled, including recurrence probes | `AnalysisError::Cancelled` |
| Circuit and DEM flattening | `CircuitFlattenLimits::with_cancellation`, `DemFlattenLimits::with_cancellation` | Every materialized instruction; every visited DEM item and repeat iteration, also through `DemFlattenedInstructionIter::with_cancellation` | `AnalysisError::Cancelled`, or `ModelError::Cancelled` from the iterator |
| Feedback inlining | `FeedbackInliningLimits::with_cancellation` | Every undone instruction and unrolled iteration | `AnalysisError::Cancelled` |
| Time reversal and QEC inverse | `TimeReversedForFlowsOptions::cancellation`, `InverseQecOptions::cancellation` | Every reversed instruction of the expanded measurement-rich reversal | `AnalysisError::Cancelled` |
| Flow generation and missing detectors | `FlowGeneratorOptions::cancellation` through `circuit_flow_generators_with_options`, `MissingDetectorOptions::cancellation` | Every undone instruction of the measurement-rich solver, and the unitary path's Tableau conversion | `AnalysisError::Cancelled` |

| Detecting regions | `DetectingRegionOptions::cancellation`, `DetectingRegionTargetOptions::cancellation` | Every undone instruction and repeat iteration of the reverse tracker | `AnalysisError::Cancelled` |
| Unsigned flow checking | `UnsignedFlowCheckOptions::cancellation` through the `*_with_options` flow checks, also reached from `TimeReversedForFlowsOptions::cancellation` for the sparse validation of time reversal | The dense Tableau conversion and every flow applied to it; every undone instruction and repeat iteration of the sparse tracker, every seeded flow term, and every extracted flow region | `AnalysisError::Cancelled`, never a flow failed closed; a Tableau refused by the budget falls back to the sparse tracker, a cancelled conversion does not |
| Pauli conjugation | `PauliConjugationOptions::cancellation` through `pauli_after_circuit_with_options`, `pauli_before_circuit_with_options` | Every folded item of the validation walk, the Tableau conversion, and every expanded instruction of the non-unitary walk | `AnalysisError::Cancelled` |
| Circuit passes | `CircuitPassContext::with_cancellation`, read by passes through `CircuitPassContext::cancellation` | Every folded item while the executor admits the input and the returned circuit, before and after each pass method, and every folded item of `WithoutNoisePass` | `CircuitPassError::Cancelled`, also for any diagnostic a pass returns while the signal is set |
| Logical-error search | `LogicalErrorSearchLimits::with_cancellation` through `shortest_graphlike_undetectable_logical_error_with_limits`, `find_undetectable_logical_error_with_limits` | Every visited DEM instruction and repeat iteration while the graph is built, every initial edge, and every examined search transition | `AnalysisError::Cancelled` |
| SAT problem generation | `SatMaterializationLimits::with_cancellation` through `shortest_error_sat_problem_with_limits`, `likeliest_error_sat_problem_with_limits` | Every traversed DEM instruction and repeat iteration of both traversal passes, every flattened error in indexing, shape preflight, and clause construction, every emitted clause, and every clause sized and serialized | `AnalysisError::Cancelled` |
| Decoding | The `&Cancellation` passed to `decode_batch` and `DecoderSession::decode_validated_batch` | Before dispatch, then between records by each implementation | `DecodeBatchStatus::Cancelled` with the exact completed prefix |
| Folded DEM traversal | `FoldedDemVisitor::poll_cancellation`, a defaulted visitor hook | Every expanded or selected repeat iteration | The visitor's error type |

`stab-algebra` operations take no signal: each call is polynomial in bytes already admitted, at most `O(n^3 / 64)` word operations for an `n`-qubit Tableau, or `O(log |k|)` such compositions for `Tableau::pow(k)`, and callers that loop over them poll between calls.
Parsing and circuit generation take no signal, because they are linear in their admitted bytes.
Sparse flow-region extraction, logical-error search transitions, and SAT clause sizing and serialization also tick within their inner qubit, term, and literal loops, so wide flows, high-degree states, and long clauses remain bounded between polls.

## Evidence

The parity ledger families under `resource-safety.*` own the byte-budget boundaries, and `stab-extensions.memory-budget` owns the CLI option; `docs/stim-parity.md` renders their selectors.

Boundary tests admit the exact budget and refuse the first excess byte before any allocation, RNG advance, or sink mutation, using the allocation counter and sink observation where the owner already did.

Hostile-shape tests keep a typed refusal for each removed cap's shape when it exceeds the budget, such as a compact repeat with an astronomical record width or flattened size.
