# Stab 0.2 API Migration Inventory

This ledger accounts for public Rust API changes made between the frozen pre-0.2 baseline and the coordinated Stab 0.2 release.

It is append-only during the migration.

The old path, replacement, rationale, and verification must be recorded before a public item is removed, renamed, or moved.

The complete discovered API remains owned by `oracle/qualification-manifest.json`; this document records intentional migration decisions instead of duplicating unchanged items.

## Status Values

- `migrated`: the old API has been removed or moved and its replacement is implemented and tested.
- `adapter`: a compatibility adapter remains temporarily while callers migrate.
- `pending`: the target replacement is specified but the old API remains current.
- `removed`: the old API had no useful supported replacement.

## Diagnostics

| Pre-0.2 API | Stab 0.2 replacement | Status | Rationale | Verification |
| --- | --- | --- | --- | --- |
| `CircuitError::InvalidResultFormat { message }` | `CircuitError::InvalidResultFormat(FormatError)` plus `CircuitError::format_error` | `migrated` | Result-format failures need stable machine codes and exact source bytes without changing the established human error prefix. The typed payload retains the message and adds severity, an optional byte span, and operation-specific context. | Exact value, conversion, display, 01, HITS, and DETS span tests; complete result-format corpus |
| Unstructured result-format error strings | `ByteSpan`, `DiagnosticSeverity`, `FormatErrorCode`, `FormatErrorContext`, and `FormatError` | `migrated` | Agents and the JSON CLI renderer need a non-lossy diagnostic contract. Private fields prevent callers from constructing internally inconsistent payloads while stable accessors expose the public contract. | `result_format_diagnostic_value_contract_is_stable` and exact grammar-span tests |
| Human-only CLI failures and deprecation warnings | Global `--error-format=human|json` with private schema-version-1 JSON Lines rendering | `migrated` | Agents need structured failures, but serialization dependencies and CLI argument policy do not belong in domain crates. The conservative raw-argument probe selects JSON only for one unambiguous request and leaves malformed arguments to Clap. | Exact human output, JSON schema and typed context, warning/error ordering, Clap, help/version, streaming absolute-span, writer-failure, and alias-preservation tests |

Packed `b8`, `r8`, and `ptb64` diagnostics now use shared byte-length validation and one inlined zero-allocation `r8` record decoder across materialized and streaming consumers. Their existing human messages and acceptance boundaries remain unchanged while stable codes, exact offending-byte or EOF spans, and typed length or run contexts are exposed. Circuit and DEM parser spans remain A2 work.

## Resource Policies And Estimates

| Pre-0.2 API | Stab 0.2 replacement | Status | Rationale | Verification |
| --- | --- | --- | --- | --- |
| Fixed circuit and DEM parser line and repeat-depth constants | `ParseLimits`, `SourceLineLimit`, `RepeatNestingLimit`, `Circuit::from_stim_str_with_limits`, and `DetectorErrorModel::from_dem_str_with_limits` | `migrated` | Line admission is configurable, but the recursive model stack still has a shared non-overridable ceiling of 256 repeat levels. Named quantities prevent swapped constructor arguments. Existing entry points delegate through the exact old defaults, source-line admission may be tightened or relaxed, and repeat admission may only be tightened until every recursive consumer supports a larger envelope. | Exact defaults, accepted maximum, first rejection, hard-ceiling rejection, circuit/DEM parity, unchanged human messages, and allocation-bounded preflight tests |
| Untyped parser resource rejection strings | `ResourceLimitError`, `ResourceOperation`, `ResourceKind`, and `CircuitError::resource_limit_error` | `migrated` | Agents need the operation, resource dimension, actual amount, and limit without parsing English. One private typed cause now derives both the compatibility-preserving human message and schema-version-1 JSON context, preventing the two views from drifting. | Core value/context assertions and exact schema-version-1 CLI JSON |
| No pre-execution parse estimate | `Estimate`, `EstimateClass`, `ResourceEstimate`, and `ParseLimits::estimate` | `migrated` | Inspection must distinguish facts from guesses. A text estimate reports input bytes and physical lines exactly; semantic expansion, memory, output, and work remain `Unknown` until their owning operation can estimate them honestly. The upper-bound vocabulary is reserved for the first operation that can produce a defensible bound and is not independently promoted by a manufactured test value. | LF, CRLF, empty, unterminated-line, exact, and unknown classification assertions |

Hard limits for target representation, DEM numeric values, detector identifiers, PTB64 shot grouping, generator domains, and stabilizer algebra are deliberately absent from `ParseLimits`. Parser preallocation samples at most a fixed prefix and is capped by admitted lines, so rejected trailing input cannot inflate allocation before admission. The broad byte-admission obligation remains planned until an operation-owned input-byte policy exists. Later compile, sampling, materialization, and search policies remain separate types owned by those operations.

## Detector Error Model Analysis

| Pre-0.2 API | Stab 0.2 replacement | Status | Rationale | Verification |
| --- | --- | --- | --- | --- |
| `DetectorErrorModel::without_tags` | `analysis::detector_error_model_without_tags` | `adapter` | Recursive tag stripping is a compact model transform and does not belong to syntax storage. | Nested-repeat preservation, non-mutation, and exact printing tests |
| `DetectorErrorModel::flattened` | `analysis::flattened_detector_error_model` | `adapter` | Repeat expansion and detector-shift application are materializing analysis with explicit admission limits. | Exact shifted output, overflow, and first-rejection tests |
| `DetectorErrorModel::rounded` | `analysis::rounded_detector_error_model` | `adapter` | Probability rounding is an explicit semantic transform over error instructions. | Pinned Stim rounding, zero retention, tag preservation, and folded-repeat tests |

The model-owned folded traversal exposes only structural summaries and deterministic compact block identities. Search eligibility, ErrorMatcher folding, and SAT nonzero-probability policies are owned by their analysis consumers so the model does not accumulate algorithm-specific caches.
