# Stab 0.2 API Migration Inventory

This ledger accounts for public Rust API changes made between the frozen pre-0.2 baseline and the coordinated Stab 0.2 release.

It is append-only during the migration.

The old path, replacement, rationale, and verification must be recorded before a public item is removed, renamed, or moved.

The complete discovered API remains owned by `oracle/qualification-manifest.json`; this document records intentional migration decisions instead of duplicating unchanged items.

## Status Values

- `migrated`: the old API has been removed or moved and its replacement is implemented and tested.
- `adapter`: a compatibility adapter remains temporarily while callers migrate.
- `pending`: the target replacement is specified but the old API remains current.
- `removed`: the old API had no useful supported replacement.

| --- | --- | --- | --- | --- |

| Unstructured result-format error strings | `ByteSpan`, `DiagnosticSeverity`, `FormatErrorCode`, `FormatErrorContext`, and `FormatError` | `migrated` | Agents and the JSON CLI renderer need a non-lossy diagnostic contract. | Circuit and DEM parser failures split across strings and line-only variants | `CircuitError::Parse(ParseError)`, `ParseErrorCode`, `ParseErrorContext`, and `CircuitError::parse_error` | `migrated` | Agents need exact source locations and stable classifications while humans retain established line-prefixed messages for behavior that was already compatible. It preserves source-order failure precedence, treats Stim comment and tag payloads as opaque bytes, and exposes exact byte serializers and tag accessors instead of applying whole-input UTF-8 normalization. Packed `b8`, `r8`, and `ptb64` diagnostics use shared byte-length validation and one inlined zero-allocation `r8` record decoder across materialized and streaming consumers. Their existing human messages and acceptance boundaries remain unchanged while stable codes, exact offending-byte or EOF spans, and typed length or run contexts are exposed.

Named quantities prevent swapped constructor arguments. | Fixed circuit and DEM flattening limits | `CircuitFlattenLimits`, `DemFlattenLimits`, and policy-aware analysis entry points | `migrated` | Explicitly materializing transforms need caller-selected output and traversal budgets without coupling the circuit and DEM operations. | Fixed detection conversion limits | `DetectionConversionLimits` plus policy-aware compile, materialized, sampling, streaming, width, count, and validation entry points | `migrated` | Per-record width, returned in-memory data, repeat unroll, expanded instruction work, aggregate repeat work, retained terms, and compiled-plan bytes grow independently. Record width, materialized data, and repeat unroll preserve their historical defaults. Audit replaced unsafe representational aggregate defaults with finite operation-safety defaults because compact repeated input could otherwise drive unbounded traversal or retention. One operation-owned policy keeps frame and reference conversion paths aligned. | Existing-entry-point equivalence, independent dimensions, real practical default boundaries, nested repeats, streaming behavior, allocation boundaries, compiled-plan admission, and typed resource context |
| Fixed DEM sampler work and buffer limits | `DemSamplerLimits` plus policy-aware materialized, replay, and streaming methods | `migrated` | Stochastic error applications, replay traversal, returned in-memory units, and the active byte footprint are distinct costs. | Test-substituted and fixed logical-error search budgets | `LogicalErrorSearchLimits` plus graphlike and hypergraph policy entry points | `migrated` | Traversal, graph construction, hyperedge retention, and search frontier state have separate growth dimensions. | Fixed SAT traversal, CNF, and output limits | `SatMaterializationLimits` plus policy-aware shortest and likeliest SAT entry points | `migrated` | SAT generation needs independent traversal, mechanism, target, variable, clause, literal, and serialized-output admission before large allocations. | Exact defaults, every dimension's accepted maximum and first rejection, two-pass traversal admission, output sizing, and typed resource context |
| No pre-execution parse estimate | `Estimate`, `EstimateClass`, `ResourceEstimate`, `ParseLimits::estimate`, and `ParseLimits::estimate_bytes` | `migrated` | Inspection must distinguish facts from guesses. The upper-bound vocabulary is reserved for the first operation that can produce a defensible bound and is not independently promoted by a manufactured test value. | LF, CRLF, opaque bytes, empty, unterminated-line, exact, and unknown classification assertions |

Hard limits for target representation, DEM numeric values, detector identifiers, PTB64 shot grouping, generator domains, stabilizer algebra, fixed CLI I/O, and still-partial analysis fallbacks are deliberately absent from these policies. Parser preallocation samples at most a fixed prefix and is capped by admitted lines, so rejected trailing input cannot inflate allocation before admission. [The A2 resource policy inventory](a2-resource-policy-inventory.md) records every reviewed family and the rationale for keeping each boundary configurable or fixed.
