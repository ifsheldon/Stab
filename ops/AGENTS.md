# Instructions For Ops Tools

- Keep operational branching, validation, report generation, release control, and subprocess orchestration in Rust binaries under `ops/`. Keep `justfiles/` recipes thin and declarative.
- `ops/oracle` owns pinned Stim validation, behavior fixtures, result-format differential testing, gate metadata comparison, and the atomic parity ledger commands. Read [../docs/README.md](../docs/README.md) before changing these workflows.
- `ops/bench` owns the single end-to-end performance suite. Read [../benchmarks/AGENTS.md](../benchmarks/AGENTS.md) before changing it.
- `ops/process` (`stab-process`) owns the shared bounded process supervisor and the measurement launcher. `ops/bench` and `ops/oracle` must run every child through it instead of growing their own copies; it requires Linux because it waits on a pidfd and reaps with `wait4`. It kills the process group before every reap, reads and writes the child's pipes without blocking, and after the group is closed waits at most a short grace for end of file, so a descendant that left the group and still holds a pipe is reported instead of hanging the supervisor. A regular-file limit requires the measured launch: the launcher lowers its own `RLIMIT_FSIZE` before spawning, so every binary that requests one must dispatch a hidden subcommand to `stab_process::run_launcher` (`stab-bench e2e-launch`, `stab-oracle process-launch`). Long-running callers check `Cancellation::is_cancelled()` at phase boundaries. The oracle gives builds and test-harness runs a separate long timeout and keeps the short one for Stim and Stab fixture runs, and it runs the `stab` binary whose path Cargo reports, never an assumed target path.
- `ops/architecture` validates crate and consumer boundaries. `ops/release` owns coordinated publication safety. `ops/pre-commit` owns staged checks, instruction-document policy, and hook installation, and reads every staged input through its `StagedTree`.
- `ops/release` keeps its own supervisor in `ops/release/src/process.rs` on purpose, built on the lower layer it shares with `stab-process` (`group::ProcessGroupLeader`, `pipe::OutputReader` with an explicit `DrainPolicy`, and `Cancellation`). It executes a retained program descriptor that it revalidates around spawn, replaces the environment with a fixed locale, `PATH`, and Git configuration while dropping inherited `GIT_*` overrides, gives the child no stdin, stops descendant-held readers after a short drain grace, and fails a capture that was still receiving data when it stopped. Those publication guarantees differ from the shared supervisor's contract, so do not merge the two upper supervisors without porting every release supervisor test and rerunning `release::check`.
- The shared no-follow primitives live in `ops/confined-fs` (`stab-confined-fs`): every open walks descriptors from `/` with `O_NOFOLLOW` on every component and accepts only absolute paths of normal components. `ops/release/src/safe_fs.rs` builds retained directories, tombstone removal, descriptor programs, sealed copies, and device and inode identity revalidation on top of them; `ops/oracle/src/safe_file.rs` uses them for fixture reads and atomic golden writes and does not revalidate identity. `cap-std` 4.0.3 was evaluated and not adopted: its `Dir` follows symlinks below the root, it has no no-follow directory open, and its `remove_dir_all` recursion is unbounded and never revalidates identity, so it would only add dependencies under the same wrappers.
- Treat subprocesses, outputs, repository paths, and generated artifacts as hostile at their declared boundaries. Preserve bounded concurrent I/O, process-group cleanup, typed paths, non-reused artifact destinations, and clear domain errors.
- Do not recreate broad qualification inventories, receipt trees, duplicate benchmark ledgers, or shell-script workflow logic.
- Run targeted tool tests while iterating, then the workspace checks and matching `just` contract command before a requested commit.
